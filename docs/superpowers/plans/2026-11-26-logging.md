# Logging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kept, traceable, auditable logs for every process, built on the user's stdlib snippet.

**Architecture:** `shared_common/common/log.py` is the user's snippet plus a daily file handler, an audit handler and a
masking formatter. The request id ContextVar is carried over HTTP (header) and gRPC (metadata) by middleware and
interceptors. Audit lines are plain `key=value` messages on the `audit` logger.

**Tech Stack:** Python 3.14 stdlib `logging`, FastAPI/uvicorn, grpc.aio, pytest. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-26-logging-design.md`

## Global Constraints
- The snippet's names, signatures and format stay exactly as given: `setup_logging(service: str) -> None`,
  `set_request_id(value: str | None = None) -> str` (new id = `uuid.uuid4().hex[:12]`), `get_request_id() -> str`,
  `_request_id` default `"-"`, format `"%(asctime)s %(levelname)-7s [%(service)s] [%(request_id)s] %(name)s: %(message)s"`,
  datefmt `"%H:%M:%S"`, `LOG_LEVEL` env, `basicConfig(..., force=True)`. Code logs with
  `logger = logging.getLogger(__name__)`, `%s` args, `logger.exception(...)` in `except`.
- Env: `LOG_DIR` (default `<repo>/logs`), `LOG_RETENTION_DAYS` (default 30, service files only). Audit files are never deleted.
- Files: `logs/<service>/<YYYY-MM-DD>.log` (all lines), `logs/audit/<service>-<YYYY-MM-DD>.log` (logger `audit` only).
  Local date; never rename a file.
- Audit lines: logger `logging.getLogger("audit")`, message `"<event> key=value key=value"`; values with spaces are
  `json.dumps`-quoted; always written whatever `LOG_LEVEL` is (the audit logger level is INFO and its handler ignores the root level).
- Metadata `x-request-id` (existing: `x-user-id`). Accepted id: `[A-Za-z0-9._-]{1,64}`; anything else → new id.
- Masking applies to the final formatted line (message and traceback) in every handler.
- A failing file write never raises (`Handler.handleError` prints one stderr line).
- Tests call `setup_logging` only with `LOG_DIR` set to `tmp_path` (monkeypatch env) and restore handlers after.
- New tests are `tests/test_logs*.py`, added to the `tests:` line in `.github/workflows/ops.yml`; `scripts/ci_test_coverage.py` must pass.
- Repo files are CRLF: edit with the Edit tool.
- One branch `logging` for all 5 tasks (user decision). Push after each task; next task only when all CI workflows
  are green. Merge `logging` to main via PR when all are green.

## Review Focus
1. Secret inside an exception traceback (DB URL with password, `gsk_` key) → masked. Task 1 `test_masks_traceback`.
2. `LOG_DIR` not writable → request still works, one stderr line. Task 1 `test_unwritable_dir_does_not_raise`.
3. Hostile `X-Request-Id` (300 chars, newline, `../`) → replaced. Task 2 `test_bad_request_id_replaced`.
4. Request ids leaking between concurrent requests → each keeps its own. Task 2 `test_ids_isolated_between_concurrent_calls`.
5. Viewer meets a half-written or foreign line → skips it, keeps going. Task 5 `test_skips_bad_lines`.

**Interfaces (produces):**
- The snippet's three functions, unchanged in signature.
- `setup_logging` additionally attaches, each with the `_Context` filter and the masking formatter:
  console (as in the snippet); `DailyFileHandler(LOG_DIR/<service>, "{date}.log", retention_days)`;
  `DailyFileHandler(LOG_DIR/"audit", f"{service}-{{date}}.log", 0)` with a filter passing only `record.name == "audit"`.
- `class DailyFileHandler(logging.Handler)`: `__init__(self, directory: Path, pattern: str, retention_days: int, today: Callable[[], date] = date.today)`;
  opens lazily, reopens when `today()` changes, on each open deletes `*.log` in `directory` whose date in the name is older than `retention_days` (0 = keep all); UTF-8; flushes each record.
- `class MaskingFormatter(logging.Formatter)`: `format()` returns `mask(super().format(record))`.
- `mask(text: str) -> str`: `gsk_[A-Za-z0-9]{10,}` → `gsk_***`; `pa-[A-Za-z0-9_-]{20,}` → `pa-***`;
  `(postgres(?:ql)?://[^:/@\s]+):[^@\s]+@` → `\1:***@`; `(?i)\b(password|passwd|token|secret|api_key|authorization)(["']?\s*[=:]\s*["']?)[^\s"',}]+` → `\1\2***`. Must not touch `prompt_tokens=5`, `tokens=1200`.
- `audit(event: str, **fields) -> None`: `logging.getLogger("audit").info(event + " " + "k=v ...")` helper, values quoted per Global Constraints.

### Task 2: Request id across HTTP and gRPC, access lines, errors (`logging/02-request-id`)

**Files:**

  `services/common/server.py` (new interceptor, first in the list), `orchestrator/routes_chat.py` (each chat turn task
  calls `set_request_id()` and logs `chat turn started conversation=… turn=… http_request=<POST's id>`),
  background loops — `orchestrator/agent/memory.py` (worker, per job), `orchestrator/order_watch.py`,
  `services/order/{recovery,fulfilment,watch}.py` — call `set_request_id()` per unit of work and log the order/turn id once.
- Test: `tests/test_logs_context.py`

**Interfaces:**
- Consumes: `set_request_id`, `get_request_id` (Task 1).
- Produces:
  - `shared_common/common/log.py`: `valid_request_id(value: str | None) -> str | None`.
  - `orchestrator/request_log.py`: `class RequestLogMiddleware` (pure ASGI): `set_request_id(valid_request_id(header))`,
    adds `X-Request-Id` response header, logs one line `"%s %s -> %d %dms user=%s"` (method, path without query, status,
    ms, user id or `-`) at INFO (`/api/health` DEBUG, 5xx ERROR); an unhandled exception → `logger.exception("unhandled %s %s", method, path)` then re-raise.
  - `services/common/server.py`: `class RequestIdInterceptor(grpc.aio.ServerInterceptor)` — wraps the method handler
    (unary-unary and unary-stream, same pattern as `_denying_handler` in `shopassist_proto/svcauth.py`) so inside the
    call it does `set_request_id(valid_request_id(md.get("x-request-id")))`, then logs `"%s -> %s %dms caller=%s user=%s"`
    (RPC name, status code name, ms, `x-caller`, `x-user-id`): OK INFO, non-OK WARNING, unexpected exception
    `logger.exception` then re-raise; health `Check` DEBUG.

### Task 5: Viewer, Docker, README (`logging/05-viewer`)

**Files:**
- Create: `scripts/logs.py`
- Modify: `docker-compose.yml` (app services: `LOG_DIR=/app/logs`, `TZ=${TZ:-UTC}`, bind mount `./logs:/app/logs`), `README.md` (short "Logs" section)
- Test: `tests/test_logs_viewer.py`

**Interfaces:** stdlib only. `parse(line: str, day: date, service: str) -> dict | None`
(fields `ts`, `level`, `service`, `request_id`, `logger`, `message`; `None` for a non-matching line; a following
traceback line is attached to the previous record), `load(log_dir: Path, days: list[date], audit: bool) -> list[dict]`
sorted by `ts`, `main(argv: list[str] | None = None) -> int`.
Flags: `--dir`, `--day` (default today; `--since` may span days), `--service`, `--level` (minimum), `--audit`
(audit files only), `--request ID`, `--user ID` (matches `user=ID`), `--order ID` (matches `order=ID`), `--since 30m|2h|1d|ISO`,
`--grep TEXT` (case-insensitive), `--follow` (poll 1 s), `--turn ID` (prints the `assistant_turn` line as a block:
message, each tool `name(args) -> result`, reply, tokens; then every line with that turn's request id).
Output: `YYYY-MM-DD HH:MM:SS LEVEL [service] [rid] logger: message`.
